Keep URL scrubbing narrowly scoped. Redact sensitive query parameters with `scrubUrl`, and scrub the `referer` header through the same helper before capture. Do not propose broad fragment/hash scrubbing unless the fragment is explicitly parsed as query-style auth data; plain SPA/hash routes are useful debugging context and should be preserved.

## 2025-01-15 - Redacting Basic Auth Credentials and Query-style Fragments in URL Scrubbing
**Vulnerability:** URL scrubbing historically only redacted standard search parameters, leaving basic auth credentials (`user:password@`) and hash/fragment query-style parameters (such as OAuth implicit flows passing `#access_token=...`) completely exposed in stack traces, HTTP requests, referrers, and breadcrumbs.
**Learning:** Basic auth credentials and fragment-based tokens bypass the traditional `URLSearchParams` on a standard `URL` object because they reside in `username`/`password` and `hash` fields respectively. A comprehensive security scrubber must inspect and filter these parts of the URL.
**Prevention:** Explicitly parse and redact URL `username` and `password` properties. Also, selectively check if `url.hash` contains query-like connectors (`=` or `&`), and if so, parse and redact its sub-parameters using `URLSearchParams` while carefully preserving normal SPA hash routes like `#/home`. Ensure the final redaction token is post-processed so `[filtered]` is not URL-encoded as `%5Bfiltered%5D`.
